# Sync Template

Confirm project provenance, source template, comparison baseline and permitted
repositories before inspection. Read the closer rules in both repositories,
preserve dirty state and classify upstream differences as applicable unchanged,
adapted, already present, conflicting or not applicable.

For an initialized project using the four-file README contract, compare the
verified previous and current source README content with its adapted guide:

- source `README.md` maps to project `TEMPLATE_README.md`;
- source `README.de.md` maps to project `TEMPLATE_README.de.md`.

Follow "Project READMEs and retained template guides" in `PROJECT_SETUP.md`.
Do not copy upstream READMEs over project `README.md` or `README.de.md`.
Preserve guide adaptations, local rules and project decisions; adopt selected
workflow changes while retaining the actual file/skill inventory, guide
identity, absent inherited badges, license notices and correct navigation.
Do not restore removed `create-local-project`, template-only `IDEAS.md` or
completed initialization instructions as locally executable ongoing work.
Update project introductions only for selected project-specific behavior or
entry-point changes. Review both affected language pairs, their cross-links
and remaining local file/skill targets before recording an applied baseline.
If older projects lack guides, propose their adoption separately, preserve
existing README content and resolve collisions; do not rerun initialization,
auto-migrate them or claim an unavailable comparison baseline.

Present the impact and proposed adoption scope before consequential edits.
Apply only selected updates, adapt them to project decisions and validate the
project independently. Never treat the repositories as a monorepo or assume
that template recency overrides project intent.
