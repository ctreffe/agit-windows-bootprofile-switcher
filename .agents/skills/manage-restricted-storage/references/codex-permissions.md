# Conditional Codex protection procedure

Load this reference only for a selected configuration or invented-only test.
It describes a procedure; it is not evidence that an app/build enforces a deny.

## Establish and configure the selected route

Identify the actual permitted runtime, platform/backend, required operations
and current profile selection. Use narrow approved program/configuration
metadata; avoid general environment dumps, logs, session stores and secrets.
Unknown selection or baseline remains an explicit gap.

Prepare a minimal configuration diff using the project's existing approved
access/network baseline and maintainer-supplied exact denied roots. Do not paste
a broad default profile, discover source paths or overwrite unrelated settings.
Confirm private paths/settings are excluded from Git before populating them.
Apply only authorized changes; no installation, ACL or global-policy change is
an incidental setup action.

Named permission profiles and older sandbox settings have selection/precedence
constraints. A stored default alone does not establish what the client uses.
Verify relevant current documentation before configuration work. Never remove
an old setting or alter managed requirements without exact scope and authority.

## Produce route-specific evidence

Agree an isolated invented-only tree/control, expected results, limits and
owned-artifact cleanup. An exception to a closed zone must explicitly cover the
exact invented path. No real source, source-derived fixture or confidential
parent listing belongs in this test.

Verify the installed binary's help before composing a CLI sandbox command.
--permission-profile/-P selects a permission profile; --profile/-p selects a
configuration layer. Preserve applicable managed requirements in the tested
route. A diagnostic route omitting them does not qualify their scope.

Use a valid allowed baseline and known marker. Exercise read, list and create
independently through the actual route. Keep fixed outcomes, not uncontrolled
diagnostics. An unexpected successful access is a failure; a denied create does
not prove denied reads. Missing markers/control failures are inconclusive.
Never escalate or switch routes to bypass the restriction under test. Clean up
only exact owned invented artifacts and record retained resources.

Check the desktop app separately when it is required. A restart, presumed menu,
profile label or passing CLI probe cannot qualify app enforcement. No desktop
repair is promised by this procedure.

## Boundaries and freshness

Local command profiles do not cover every connector, MCP, browser, computer-use,
cloud or approved-escalation route. Native Windows managed deny_read alone does
not cover shell subprocess reads. Keep those routes explicit in requirements.
Reassess affected evidence after runtime, session, profile, path, fallback or
tool changes. Keep failed attempts and distinguish stale evidence from a current
pass. Protected work and disclosure remain under the project's own authority.
